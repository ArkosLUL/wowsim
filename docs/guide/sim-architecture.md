# Sim architecture

Where the code this fork touches lives. Everything else follows the upstream layout.

## sim/core

| File | Holds |
|---|---|
| `target.go` | targets, `AttackTable`, the default level-83 boss, the AoE target cap |
| `spell_outcome.go` | every `Outcome*` roll, including enemy vs player |
| `spell_result.go` | hit, crit, expertise |
| `spell_resistances.go` | armor and magic resistance |
| `combat_table.go` | the server's combat tables, in integer basis points |
| `flags.go` | `SpellFlag*` |
| `constants.go`, `unit.go`, `avoid_dr.go` | level constants, armor penetration, player avoidance diminishing returns (per class) |
| `base_stats.go`, `base_stats_auto_gen.go` | base stats and rating conversions, generated from the server by `tools/acore/gen_basestats` ([README](../../tools/acore/gen_basestats/README.md)) |
| `character.go`, `mana.go` | stat dependencies. `BaseStatsRace` sets base stats; `RacialTraits` picks racial abilities |
| `server_settings.go`, `server_defaults_auto_gen.go` | the encounter's `ServerSettings` as `Raid.Server`, read with `Character.Server()`. Unset fields take the live values from `tools/acore/gen_server_defaults` ([README](../../tools/acore/gen_server_defaults/README.md)) |
| `serverdata/` | the server's per-spell data (timing, flags, effects), `spell_proc`, `spell_bonus_data` and `spell_enchant_proc_data`, by spell id. Generated by `tools/acore/gen_serverdata` ([README](../../tools/acore/gen_serverdata/README.md)) for the sim's spell-id constants and what they trigger. It must not import `sim/core` |
| `racials.go`, `buffs.go`, `debuffs.go`, `consumes.go` | racials, raid buffs, armor debuffs, consumables |
| `attack.go`, `rage.go`, `dot.go`, `cast.go` | swings, rage, DoTs, casts |
| `database.go`, `database_load.go` | item DB. `Item.TotalStats()` is item + enchant + gems + socket bonus. The `with_db` build tag embeds the DB. The global maps sit behind `dbMu`: after init, write with `AddToDatabase` and read with `Lookup*` |
| `reforging.go` | mod-reforging rules, mirrored in `ui/core/proto_utils/reforging.ts` |
| `professions.go` | any number of professions; falls back to `profession1`/`profession2` |
| `item_swaps.go`, `bulksim.go` | item swaps (the same item id never swaps); bulk sim, where candidates inherit a reforge valid on them |
| `test_suite.go` | the golden-file harness |

Quirk: `UnitLevelFloat64` in `utils.go` treats every level outside 80–82 as +3.

## Classes, items, encounters

- `sim/<class>/`: class code. Core sets the class stat dependencies: `addClassStatDependencies` adds
  Str/Agi → AP/RAP and Agi → crit, and `NewCharacter` sets melee haste and ArP per class from the
  generated scalars.
  - Hunter ×1.15 ranged speed: `hunter/hunter.go`.
- Pets: `hunter/pet.go`, `shaman/fire_elemental_pet.go`, `shaman/spirit_wolves.go`, `warlock/pet.go`,
  `deathknight/ghoul_pet.go`.
- Item effects: `sim/common/{wotlk,tbc}`. Class set bonuses: `sim/<class>/items.go`. An effect's closure
  runs once per character, concurrently across sims (optimizer, stat weights, web requests), so copy a
  captured config before changing it.
- Boss AIs, still with Classic numbers: `sim/encounters/{naxxramas,ulduar,toc,icc}`.
- `sim/web/main.go` is the server, with flags `--usefs`, `--wasm`, `--host` and `--launch`.
- `sim/optimizer/`: the BiS gear optimizer ([PLAN](../bis-optimizer/bis-optimizer.PLAN.md)), with its
  contract in `types.go` and `proto/optimizer.proto`. `wowsimcli optimize`, `/optimizeGearAsync` and the
  wasm export run it. `evaluator.go` runs loadouts as paired, sharded sims behind the `Evaluator` seam;
  `objective.go`, `response.go` and `residuals.go` turn the results into the search's score.

## Protos

- `proto/api.proto` holds `RaidSimRequest`, `Player` and `OptimizeGearRequest`. `common.proto` holds
  `Target`, `Encounter`, `ItemSpec` and the enums. `ui.proto` holds the saved settings, and
  `optimizer.proto` the optimizer's messages.
- Fork fields:
  - `ItemSpec.reforge` (`ItemReforge`, raw server stat-type ids)
  - `Player.racial_traits`
  - `Player.professions`, with `profession1`/`profession2` kept for old links and presets
  - `SavedSettings.racial_traits`
  - `Encounter.raid_difficulty` and `Encounter.server_settings`

## UI

- `ui/core/player.ts`: player state. `setProfessions` is the only professions setter, and it sorts, so
  share links are deterministic.
- `ui/core/components/individual_sim_ui/settings_tab.ts`: the Racial Traits and professions pickers.
- `ui/core/components/gear_picker.tsx`: gear, gems, enchants, and the Reforging tab.
- `ui/core/encounter.ts` sets the default target. `ui/core/constants/mechanics.ts` holds the UI copies
  of the mechanic constants and re-exports the generated `ratings_auto_gen.ts`.
  `server_defaults_auto_gen.ts` holds the live server settings.
- `ui/<spec>/presets.ts` and `ui/<spec>/gear_sets/*.gear.json`: presets.
- `ui/raid/raid_sim_ui.ts`: the raid sim, where importers are registered.

## Tools

- `tools/database/gen_db`: the item DB build. `make items` runs its AzerothCore mode
  ([README](../../tools/database/gen_db/README.md)).
- `tools/database/azerothcore`: shared MySQL and DBC readers, item conversion, roster building and the
  server catalog's tier rules (`catalog*.go`). It's kept library-shaped so a sim-server endpoint can reuse
  it.
- Thin mains: `tools/database/acdiff` ([README](../../tools/database/acdiff/README.md)),
  `tools/database/acraid` ([README](../../tools/database/acraid/README.md)) and `tools/database/accatalog`
  ([README](../../tools/database/accatalog/README.md)), which writes `assets/database/server_catalog.json`:
  every obtainable item's progression tier, sources and limits.
- `tools/acore/` (`dock.sh`, `gen_basestats`, `gen_server_defaults`, `spellids`
  ([README](../../tools/acore/spellids/README.md)), `gen_serverdata`) and `tools/simval`.
